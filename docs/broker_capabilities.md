## Evidence levels

| Level | Meaning |
| --- | --- |
| `documented` | Stated in current official documentation. It has not been exercised. |
| `paper_demonstrated` | Exercised against the broker's paper or demo environment. None exist yet. |
| `live_confirmed` | Confirmed for the intended live account. None exist yet. Live use requires this level. |
| `replay_simulated` | A property of the project's own replay broker only. |
| `UNKNOWN` | Not established, or conflicting. **Treated as disabled.** |

Paper evidence never certifies live availability. Fractional limit, stop, stop-limit, bracket/OCO and extended-hours orders are separate capabilities.

## Re-verification on 2026-11-07 (Alpaca fractional trading page)

The page body says Alpaca "supports fractional trading for market, limit, stop & stop limit orders", with `time_in_force` set to `day`. It also mentions extended-hours fractional limit orders.

The closing disclaimer on the same page still says fractional trades "can only be bought or sold with market orders during normal market hours". As markets_and_brokers.md §2 requires, this conflict is recorded as **unresolved**:

- `fractional.limit.day` stays UNKNOWN until it is demonstrated in paper (M4).
- The replay demonstrator uses limit entries. The paper adapter must demonstrate them before they are enabled for Alpaca.

The page also says fractional short sales are not supported. That matches the long-only v1 rule.

## Account rules and regulation

| Topic | Status |
| --- | --- |
| Account-rule profile | Every profile is `UNVERIFIED`. The code blocks live entries for `UNVERIFIED` (`risk/account_rules.py`). |
| Rule changes | FINRA Regulatory Notice 26-10 replaced the PDT framework from 2026-06-04, but brokers may keep applying the legacy regime until 2027-10-20. The broker's implementation for the actual account decides which profile applies: `LEGACY_PDT`, `NEW_INTRADAY_MARGIN` or `TRUE_CASH`. |
| Alpaca account type | Described as margin or limited-margin. "No borrowing" in this project does not change the legal account type. |
| Germany eligibility | Alpaca, IBKR, Kraken (spot under MiCA), Capital.com and IG are all **unverified** for the owner's actual residence and entity. |
| Funding | No adapter exposes funding or withdrawal operations (`uses_funding_endpoints: false` is enforced by the schema). |

## Exit combinations needed before any live use

| Requirement | Alpaca | Kraken | Capital.com |
| --- | --- | --- | --- |
| Fractional or tiny-size native protective stop at the exact size | UNKNOWN | UNKNOWN (fee-adjusted size issue) | UNKNOWN (minimum stop distance) |
| Atomic OCO bracket | UNKNOWN | **No**: conditional close creates one secondary order per fill | n/a (stop and limit levels attached to a deal) |
| Close of an identified position | Sell the owned quantity | Sell the owned quantity minus base-asset fees | Close by deal ID (an opposite order may open a hedge) |
| Dead-man timer | n/a | `CancelAllOrdersAfter` cancels **all** orders, protection included, so it stays disabled (enforced by `BrokerCapabilities` validation) | n/a |

The policy requires native protection for live use (`native_protection_required_for_live: true`). No adapter meets it today. Replay and paper use monitored synthetic exits (ADR-0005); they cannot protect positions during a full outage.

## Unresolved items (blockers for G0/G4)

1. **Alpaca:** fractional limit/stop/bracket support, commission and regulatory pass-through rounding, account rule profile, non-US eligibility for the owner, and the funding route and cost.
2. **IBKR:** whether fractional API orders work for ordinary stocks at all. The documentation is contradictory.
3. **Kraken:** the account fee tier, pair minimums, tiny-size stop behaviour, idempotency of the client reference, and UAT onboarding.
4. **Coinbase Advanced:** the sandbox is static mocks, so fills cannot be demonstrated.
5. **Capital.com / IG:** instrument metadata, financing rates, minimum stop distance and API terms for the owner's entity.
