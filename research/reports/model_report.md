- Selection protocol: Per walk-forward fold (purged and embargoed by the maximum hold): the scaler and model are fitted on training-window labels only; the grid point with the lowest validation log-loss is kept; the calibration map is fitted on validation scores; the threshold is chosen on validation by the net PnL per session of an engine replay of the validation window with the model filter (at least min_accepts accepted validation candidates; ties to the lower threshold). A fold that cannot be trained vetoes every candidate in its test window. The test window is never an input to training or selection. Each test window is replayed for: rule only, rule + model filter, random rejection at the model's realised veto rate (N salts) and equal accepted-candidate counts (N salts). Study walk-forward: per fold deploy the trial with the highest positive validation objective, else hold cash. Selection-aware checks: bootstrap reality check across every variant of every trial on the test windows and the deflated Sharpe ratio with N = all registered trials. The locked final test period is not used.
- Threshold rule: on validation only: among thresholds whose calibrated probability accepts at least min_accepts validation candidates, the one with the highest net PnL per session of an engine replay of the validation window (fresh USD 50 ledger, the study's policy, fees and fills; the bundle as ModelThresholdFilter accepting p >= threshold; outcome bars up to the test start); ties go to the lower threshold.
- Controls: every test window, fresh USD 50 ledger, same costs: rule only; random rejection at the model's realised veto rate in that window (HashRandomReject, one salt per seed); equal accepted-candidate count per window (TurnoverMatchedReject, one salt per seed).
- Untrainable fold: a fold without a trainable model (one outcome class, too few candidates, or no threshold with enough accepts) vetoes every candidate in its test window (fail closed: cash).

## 9. Bias and limitations

- A filter can only select from the rule's candidates; it cannot create an edge the candidates do not contain.
- The crypto baseline found no gross edge: with zero commission every rule trial was still negative after the assumed spread and slippage (research/reports/baseline_report.md), so a crypto filter starts from candidates without an edge.
- The validation window chooses the grid point, fits the calibration map and chooses the threshold, so validation figures are optimistic; only the test windows are out-of-sample.
- Labels simulate each candidate alone from a fresh USD 50 ledger. In the engine, pauses, entry limits, a pending entry and busy instruments act after the filter, so realised trades are a subset of the accepted candidates.
- The equal-turnover control matches the number of accepted candidates per test window, not USD turnover; the random control matches the veto rate only in expectation.
- A fold without a trainable model vetoes every candidate (cash), and its controls then trade nothing either.
- Bar-only replay: no quotes, queue position or intrabar path; costs are the base study's registered assumptions.
- Model checksums reproduce only with the recorded library versions; the registration binds them, so a changed environment needs a new registered trial.
- The walk-forward series is short relative to the G2 floor of 120 effective sessions and 100 trades unless stated otherwise above; uncertainty intervals are wide.
